FICHES DU PROJET AI_2AI
=======================

1. PRESENTATION
---------------
Projet Django de chatbot personnalisable avec gestion de personas, credits, recharges, API compatible OpenAI et atelier de prototypage code.

Technologies principales:
- Django 6.1+
- SQLite
- HTML, CSS et JavaScript vanilla
- Stripe
- API externes Anthropic/OpenAI compatibles

Applications Django:
- chat: chatbot, modeles IA, fournisseurs et atelier DAP
- ai_user: utilisateurs, authentification, credits et paiements
- api: API compatible OpenAI

2. ROUTES PRINCIPALES
---------------------
Dans ai_2ai/urls.py:
- /admin/ : administration Django
- /api/ : page de documentation API
- /v1/ : endpoints API compatibles OpenAI
- /auth/ : page connexion/inscription
- /login/ : connexion
- /signup/ : inscription
- /telegram/auth/ : authentification Telegram
- /whatsapp/send-otp/ : endpoint WhatsApp non finalise
- /recharge/ : page de recharge
- /recharge/create-checkout/ : creation session Stripe
- /recharge/mobile-money/ : tentative Mobile Money
- /recharge/success/ : retour apres paiement
- /recharge/webhook/ : webhook Stripe
- / : chatbot principal
- /dap/ : atelier dev and prod

3. APPLICATION CHAT
-------------------
Fichiers principaux:
- chat/models.py
- chat/views.py
- chat/urls.py
- chat/admin.py
- chat/templates/chat.html
- chat/templates/dap.html

Modeles:

APIProvider:
- name, slug, base_url, docs_url
- is_active, created_at
- represente un fournisseur externe d'IA

AIModel:
- provider, name, model_id
- is_active, created_at
- represente un modele disponible

APIKey:
- provider, name, key
- is_active, created_at, last_used_at
- la cle possede une propriete masked_key
- les cles sont actuellement stockees en clair en base

Vue chat_home:
- exige une authentification
- redirige vers /auth/?next=/ si l'utilisateur est anonyme
- transmet les modeles actifs au template
- transmet le solde de credits

Vue dap_home:
- exige une authentification
- redirige vers /auth/?next=/dap/ si necessaire
- affiche dap.html

4. CHAT PRINCIPAL
-----------------
Template: chat/templates/chat.html

Interface:
- barre laterale gauche
- conversations
- personas
- zone de messages
- panneau de personnalisation
- compteur et jauge de credits
- zone de saisie
- menu mobile

Personas par defaut:
- Assistant general
- Tuteur de langues
- Coach code

Chaque persona contient:
- id
- name
- prompt
- tone
- temp
- length

Les personas sont actuellement geres uniquement en JavaScript et disparaissent au rechargement.

Conversations:
- creees en JavaScript
- titre initial: Nouvelle conversation
- titre ensuite derive du premier message
- messages conserves uniquement en memoire navigateur
- aucune persistance serveur actuelle

Generation des reponses:

Mode demo:
- actif sans cle API
- reponse generee localement
- aucun appel reseau

Mode API direct:
- si state.apiKey est rempli, appel direct a Anthropic
- URL: https://api.anthropic.com/v1/messages
- la cle est exposee cote navigateur
- recommande pour production: passer par le backend

Credits frontend:
- estimation approximative: longueur du texte / 4
- deduction du message utilisateur
- deduction de la reponse
- affichage de l'historique local
- notification coloree si credits insuffisants

Limitation importante:
- les deductions du chat ne sont pas faites cote serveur
- CreditAccount.debit() n'est pas appele par chat.html
- un rechargement peut donc contourner le solde frontend

5. PERSONNALISATION
--------------------
Le bouton Personnaliser active le mode customize-mode.

Fonctionnalites:
- affichage pleine page du panneau de personnalisation
- panneau Persona actif
- prompt systeme
- ton
- temperature
- longueur des reponses
- nom du bot
- avatar emoji
- couleurs d'accent
- theme clair/sombre
- retour au chat
- gestion du bouton retour Android/navigateur

Apparence:
- nom du bot et avatar verrouilles par defaut
- clic sur crayon pour modifier
- reverrouillage a la sortie du champ
- sauvegarde localStorage sous ai2ai-appearance
- titre de l'onglet modifie dynamiquement
- favicon genere dynamiquement depuis l'emoji

6. MENU MOBILE
--------------

- bouton hamburger
- panneau lateral gauche superpose
- bouton de fermeture
- voile sombre derriere le menu

Le mode Personnaliser retire le menu mobile et le voile pour eviter une page sombre ou inutilisable.

7. PAGE DEV AND PROD
--------------------
Template: chat/templates/dap.html
URL: /dap/

Interface:
- editeur de code a gauche
- apercu du resultat a droite
- zone de prompt en bas a gauche
- bouton Executer
- bouton Reinitialiser
- numeros de lignes

8. APPLICATION AI_USER
-----------------------
Fichiers principaux:
- ai_user/models.py
- ai_user/views.py
- ai_user/signals.py
- ai_user/urls.py
- ai_user/admin.py
- ai_user/templates/losign.html
- ai_user/templates/recharge.html
- ai_user/templates/recharge_success.html

Modeles:

TelegramIdentity:
- lie un compte Django a un identifiant Telegram
- stocke username, first_name, last_name

CreditAccount:
- un compte par utilisateur
- balance
- credit(amount)
- debit(amount)
- bloque les debits superieurs au solde

CreditTransaction:
- historique des recharges et consommations
- amount positif pour un credit
- amount negatif pour un debit
- reasons: recharge, usage, adjustment

RechargePurchase:
- user
- stripe_session_id
- amount_cents
- credits
- status
- created_at, paid_at

Signal:
- chaque nouvel utilisateur recoit automatiquement un CreditAccount
- solde initial actuel: 0

Authentification classique:
- login par username/password
- inscription manuelle
- redirection next securisee

Telegram:
- validation HMAC du widget Telegram
- verification de auth_date
- creation ou recuperation de l'utilisateur
- connexion automatique

WhatsApp:
- interface presente
- endpoint encore non implemente
- retourne actuellement 501

9. RECHARGES
------------
Plans definis:
- 5 dollars: 50 000 credits
- 10 dollars: 110 000 credits
- 25 dollars: 300 000 credits

Regle generale:
- 1 dollar = 10 000 credits

Stripe:
- creation d'une Checkout Session
- metadata avec user_id et credits
- webhook checkout.session.completed
- creation idempotente de RechargePurchase
- credit du compte utilisateur apres confirmation

Mobile Money:
Operateurs visibles:
- Wave
- Orange Money
- Momo
- Moov Money

Le backend valide montant, operateur et numero puis retourne 503 car aucun prestataire n'est configure.

10. APPLICATION API
-------------------
Fichiers principaux:
- api/views.py
- api/urls.py
- api/templates/api.html

Endpoints:
- GET /api/
- GET /v1/models
- POST /v1/chat/completions

Authentification:
- variable API_COMPATIBLE_KEY
- header Authorization: Bearer <cle>
- si aucune cle et DEBUG=True, l'API est autorisee

/models:
- retourne les modeles actifs
- format de liste compatible OpenAI

/chat/completions:
- POST uniquement
- validation JSON et messages
- recherche du modele actif
- selection du fournisseur et de sa premiere cle active
- appel externe
- conversion Anthropic vers format OpenAI
- streaming non supporte
- mise a jour de last_used_at

Limites:
- pas de streaming
- pas de rate limiting
- pas de quotas
- pas de debit de credits
- cles stockees en clair
- erreurs fournisseur partiellement renvoyees
