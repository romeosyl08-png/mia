Utiliser Barrassons

Barrassons est un assistant en ligne de commande qui lit et recherche dans le projet courant, puis peut proposer des modifications ou exécuter des commandes avec ta confirmation.

1. Installer

Ouvre un terminal sur l’ordinateur où se trouve le dépôt, puis installe l’outil depuis le dossier du projet :

cd /chemin/vers/ai_2ai
pipx install .

Si pipx n’est pas installé, installe-le avec le gestionnaire Python de ta distribution, puis relance ces commandes. Le dépôt contient le paquet Barrassons et son exécutable.

2. Créer une clé API

  1. Reste sur cette page avec ta session AI2AI connectée, puis ouvre Clés API.
  2. Donne un nom reconnaissable, par exemple Barrassons local, et clique sur Créer.
  3. La clé complète n’est affichée qu’une seule fois. Copie-la directement dans l’invite Barrassons du terminal; ne la colle pas dans une conversation, un fichier du dépôt ou une capture d’écran.

Si une clé a déjà été partagée par erreur, révoque-la ici et crée-en une nouvelle.

3. Se connecter à la bonne API

Lance Barrassons depuis le dossier que tu veux lui faire analyser :

cd /chemin/vers/ai_2ai
barrassons

Au premier lancement, choisis 1 pour ouvrir la page des clés API, ou 2 si tu as déjà une clé. À l’invite d’URL, utilise l’adresse correspondant à ton serveur :

Serveur local
http://127.0.0.1:8000/v1
Démarre Django localement avant Barrassons et garde le serveur lancé.
Serveur Render
https://mia-vkl1.onrender.com/v1
Choisis cette URL si la clé a été créée sur l’instance Render.

Saisis ensuite la clé dans le terminal. Elle est enregistrée dans ~/.config/barrassons/config.json avec des permissions privées; elle n’est pas nécessaire dans le dépôt.

4. Choisir un modèle et travailler

Barrassons demande la liste des modèles disponibles, puis te laisse choisir par numéro ou identifiant. Il filtre les modèles qui ne prennent pas en charge les appels d’outils utilisés par cette version.

Décris une tâche précise et indique si tu veux seulement une analyse ou une modification. Par exemple :

Analyse le flux d’envoi des messages. Explique le problème et ne modifie aucun fichier.

Lis les tests de l’application, identifie ceux qui couvrent les personas,
puis propose un test manquant sans l’ajouter.

Pour quitter, écris /exit. /clear efface le contexte de la session, et /help rappelle les commandes disponibles.

5. Comprendre les confirmations

  • La lecture, la recherche et la liste des fichiers sont disponibles directement.
  • Avant d’écrire ou modifier un fichier, Barrassons affiche le chemin et demande confirmation. Réponds y pour autoriser; la réponse par défaut est non.
  • Avant une commande shell, il affiche la commande et le dossier d’exécution. Vérifie-la avant de répondre.
  • Les commandes shell sont exécutées dans le dossier courant de Barrassons. N’autorise que les commandes que tu comprends et souhaites lancer.

6. Sécurité et crédits

Les appels modèle débitent les crédits du compte associé à la clé. Une clé doit rester privée : ne la versionne pas et ne la colle pas dans les demandes adressées à l’assistant.

Pour changer de compte ou d’URL, lance barrassons login. Pour effacer la configuration locale, lance barrassons logout; cela supprime le fichier local, mais ne révoque pas la clé sur le serveur. Révoque-la aussi depuis la page Clés API si elle n’est plus utilisée.
