AI2AI · OUTIL DE DÉVELOPPEMENT

Ton projet, une demande.

Lance Barrassons dans ton projet et décris ce que tu veux faire. Il lit le code, propose les changements et te demande confirmation avant de modifier un fichier ou de lancer une commande.

1. Installer

Ouvre un terminal sur l’ordinateur où se trouve le dépôt, puis installe l’outil depuis le dossier du projet :

cd /chemin/vers/ai_2ai
pipx install .

Si pipx n’est pas installé, installe-le avec le gestionnaire Python de ta distribution, puis relance ces commandes. Le dépôt contient le paquet Barrassons et son exécutable.

2. Lancer

cd /chemin/vers/ton-projet
barrassons

Au premier lancement, colle ta clé API dans la saisie masquée. Si tu n’en as pas, appuie sur Entrée pour ouvrir Clés API et en créer une. La connexion est enregistrée pour les prochains lancements.

Un modèle compatible est choisi automatiquement. Tu peux commencer à écrire tout de suite.

3. Demander

Explique comment fonctionne ce projet.

Corrige le bug de connexion et vérifie les tests.

Écris ta demande après ❯. Relis les changements proposés, puis réponds o pour les autoriser. /undo annule la dernière modification après confirmation et /exit quitte.

/help rappelle l’essentiel. /model permet de changer d’IA.

Les thèmes de Big Persona

Barrassons reprend le thème clair ou sombre et la couleur de ton Big Persona à chaque lancement. Modifie son apparence dans Paramètres, ou choisis directement dans le terminal avec /theme.

  • Violet
  • Ambre
  • Sarcelle
  • Brique
  • Vert
/theme sombre
/theme sarcelle
/theme persona

Un choix local est mémorisé. /theme persona récupère l’apparence actuelle de Big Persona et réactive sa synchronisation au lancement. Cette synchronisation concerne uniquement le thème et la couleur. --no-color désactive les couleurs.

Aller plus loin : connexion, modèles, mémoire et outils

Changer de serveur

Le serveur enregistré est réutilisé ; Render est le choix par défaut.

Serveur local
barrassons login --api-base http://127.0.0.1:8000/v1
Démarre Django localement avant Barrassons et garde le serveur lancé.
Serveur Render
barrassons login
Utilise une clé créée sur l’instance Render. Pour revenir explicitement à Render : barrassons login --api-base https://mia-vkl1.onrender.com/v1.

Colle la clé seulement à l’invite Clé API AI2AI (saisie masquée). Aucun caractère ne s’affiche pendant la saisie. La connexion est vérifiée avant d’être enregistrée dans ~/.config/barrassons/config.json avec des permissions privées. Lance ensuite barrassons pour travailler.

Choisir un modèle

/model ouvre le catalogue, avec dix modèles par page. Choisis par numéro ou identifiant, ou saisis un nom pour rechercher. /suivant et /précédent changent de page. Ton choix est mémorisé.

Le modèle choisi doit accepter les appels d’outils compatibles OpenAI. Les modèles Anthropic ne sont actuellement pas pris en charge par ce CLI. Pour choisir directement un modèle du catalogue, lance barrassons --model identifiant-du-modele.

Décris une tâche précise et indique si tu veux seulement une analyse ou une modification. Par exemple :

Analyse le flux d’envoi des messages. Explique le problème et ne modifie aucun fichier.

Lis les tests de l’application, identifie ceux qui couvrent les personas,
puis propose un test manquant sans l’ajouter.

Tab complète les commandes et les flèches parcourent l’historique. Termine une ligne par \ puis Entrée pour continuer sur la ligne suivante. /status affiche la connexion et les jetons, /verbose développe les résultats des outils et /help tout rappelle toutes les commandes.

Reprendre une session et contrôler les changements

Les échanges et les sauvegardes des modifications sont conservés localement pour chaque dossier de travail. Pour retrouver la session d’un projet, relance Barrassons depuis ce même dossier :

barrassons --resume

Les appels d’outils interrompus sont signalés à la reprise et ne sont pas réexécutés automatiquement.

  • /diff affiche les changements des fichiers suivis par Git par rapport à HEAD. Pour les nouveaux fichiers non suivis, utilise git status.
  • /review envoie ce diff au modèle pour rechercher les bugs, les régressions et les vérifications manquantes.
  • /undo propose d’annuler la dernière édition enregistrée par Barrassons, après confirmation. L’annulation est refusée si le fichier a changé depuis, pour préserver tes modifications ultérieures.
  • /clear efface le contexte de conversation de la session sans annuler les changements dans les fichiers.

Lancer les tests et corriger les erreurs

Indique la commande de vérification adaptée à ton projet au démarrage. Tu peux aussi la combiner avec la reprise d’une session :

barrassons --test-command "python -m pytest"
barrassons --resume --test-command "npm test"

/verify lance la commande configurée après ta confirmation et ajoute son résultat à la conversation.

Avec --test-command, Barrassons lance aussi une vérification avant de conclure après des modifications. Si elle échoue, le résultat revient au modèle pour qu’il tente une correction. Cette boucle est limitée à deux vérifications automatiques par demande, chacune avec confirmation. Une commande de tests déjà réussie après la dernière modification évite une nouvelle exécution. Une vérification refusée ou toujours en échec reste signalée.

Travailler sur une branche Git isolée

Pour travailler dans un dossier séparé avec une nouvelle branche, lance :

barrassons --worktree --test-command "npm test"

Après confirmation, Barrassons crée un worktree à partir de HEAD. Le dépôt doit être propre : enregistre tes changements avant de lancer cette option. Le terminal affiche le nouveau dossier et sa branche ; les fichiers de ton dossier d’origine restent intacts.

Tu peux y consulter /diff, demander /review, puis préparer un commit ou une demande de fusion avec tes outils Git habituels. Pour reprendre cette session plus tard, place-toi dans le dossier du worktree et lance barrassons --resume.

Utiliser Barrassons dans VS Code

Le dépôt contient une extension dans integrations/vscode/. Elle ouvre Barrassons dans le terminal intégré du projet sélectionné et propose deux commandes dans la palette :

  • Barrassons : ouvrir dans ce projet démarre une session dans le dossier choisi.
  • Barrassons : reprendre la session démarre avec --resume.

Pour l’essayer, charge l’extension avec Extension Development Host dans VS Code. L’exécutable barrassons doit être installé et accessible dans le PATH. L’extension n’est pas encore publiée sur le Marketplace.

Lier la mémoire de Barrassons, Bara et du chat

Dans Ma mémoire → Lier la mémoire entre les assistants, choisis les assistants qui peuvent utiliser tes préférences personnelles. Pour partager la mémoire d’un projet, ouvre Mémoire dans cet espace Bara et active son lien Barrassons. Le lien Chat s’applique lorsque ce projet est sélectionné dans le chat.

Dans Barrassons, /memory affiche les mémoires disponibles et les identifiants des projets accessibles. Choisis ensuite ce que tu veux lier au dossier local :

/memory chat
/memory bara 42
/memory both 42
/memory off

chat utilise la mémoire personnelle, bara celle du projet, both les deux et off délie ce dossier. Remplace 42 par l’identifiant affiché pour ton projet. Tu peux aussi choisir au démarrage :

barrassons --memory chat
barrassons --memory both --memory-workspace 42

Le choix est conservé pour ce dossier et cette connexion. Le serveur relit la mémoire et les autorisations à chaque appel : modifier ou désactiver une mémoire dans 2AI prend effet dès l’appel suivant. Les liens Barrassons sont désactivés par défaut et la mémoire partagée n’est pas copiée dans les sauvegardes locales de session.

/remember Utiliser pytest pour les tests de ce projet. affiche un aperçu puis demande confirmation avant d’ajouter ce souvenir à la mémoire liée. Si un projet Bara est lié, le souvenir est ajouté au projet ; sinon, il rejoint la mémoire personnelle. Seul le propriétaire peut modifier la mémoire d’un projet. Les modifications simultanées sont bloquées jusqu’à une nouvelle relecture.

Ces options partagent uniquement les souvenirs enregistrés. Elles ne transfèrent pas les historiques, le code du dossier ni les fichiers entre les assistants. Les conversations temporaires gardent leur sélection de mémoire indépendante.

Comprendre les confirmations

  • La lecture, la recherche et la liste des fichiers sont disponibles directement.
  • Avant d’écrire ou modifier un fichier, Barrassons affiche un diff, le chemin et une demande de confirmation. Réponds o ou oui pour autoriser ; y est aussi accepté. La réponse par défaut est non.
  • Avant une commande shell, il affiche la commande et le dossier d’exécution. Vérifie-la avant de répondre.
  • Les commandes shell sont exécutées avec les droits de ton terminal dans le dossier de travail de Barrassons, ou dans le worktree si tu as choisi cette option. N’autorise que les commandes que tu comprends et souhaites lancer.

Sécurité et jetons

Les appels modèle débitent le même solde de jetons que Chat et Bara, sur le compte associé à la clé. Une clé doit rester privée : ne la versionne pas et ne la colle pas dans les demandes adressées à l’assistant.

Les sessions et sauvegardes sont enregistrées dans ~/.config/barrassons/sessions/ avec des permissions privées. Elles peuvent contenir du code et des résultats d’outils ; la clé API de configuration n’y est pas ajoutée. La commande barrassons logout ne supprime pas ces sessions.

Pour changer de clé, lance barrassons login. Pour changer de serveur, utilise barrassons login --api-base URL. barrassons logout efface la configuration locale, mais ne révoque pas la clé sur le serveur. Révoque-la aussi depuis la page Clés API si elle n’est plus utilisée.
